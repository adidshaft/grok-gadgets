# Signed updates over the relay — 17 October 2026

Phase 12b ([#342](https://github.com/adidshaft/grok-gadgets/issues/342), [ADR 012](../decisions/012-signed-updates.md)). The owner's ESP32-S3 OLED kit took signed firmware updates from the owner's relay with no cable. It refused a wrong key and a changed byte, and went back to the previous image by itself when a new one never came Online. Times are UTC. The owner authorized each step below in the session.

Evidence levels:

- **Log**: the relay's request log, read after each step (`update_*`, `device_*` and `mcp_*` lines).
- **Console**: the kit's USB console `status` reply. The kit stayed on the Mac's USB port for power.
- **Owner**: what the owner saw on the OLED and in Grok Bot.

## Owner approvals (STOP gates)

Each gate waited for the owner's yes in the session, on 17 October 2026, in this order:

1. ADR 012 as proposed: Phase 12b before Phase 12, only the relay operator pushes, core 2.0.17, anti-rollback off, 5-minute revert limit.
2. The "Before you distribute" note and the licence checklist as written; no kit binary as a release asset yet.
3. The last USB flash of the kit.
4. The relay backup and the upgrade to the candidate.
5. Each push: version N+1; the wrong key and the changed byte; the dark-screen fix; the revert test; the power cut.

## Found during the run

- **Dark OLED (ESP32 [#148](https://github.com/adidshaft/grok-gadgets-esp32-sdk/issues/148)).** After the changed-byte download (item 4b) the owner found the OLED dark. The relay log showed the kit still polling. A USB replug at 16:15:00 brought the display back. When it went dark is not known. The likely cause is that the display lost its state during a minute of flash writes; this is not confirmed. Fix in [#149](https://github.com/adidshaft/grok-gadgets-esp32-sdk/pull/149): clear the I2C bus before the boot probe, set the OLED up again after each download, and report `display` in console status. The kit took the fix as signed update `.17.6` (16:26:12–16:27:28). The OLED stayed lit through that download, its restart, the revert test and the power-cut test.
- **Status after a revert (gateway [#212](https://github.com/adidshaft/grok-gadgets-gateway/pull/212)).** The old image refuses the re-offered version just after it reports the revert. `firmware status` then showed `rejected (version)` instead of `reverted (not_online)`. Fixed: the status keeps `reverted`; both lines stay in the log.
- **Grok Bot sign-in expiry (gateway [#211](https://github.com/adidshaft/grok-gadgets-gateway/issues/211)).** Not part of Phase 12b. A new sign-in was needed for item 3d.

## Not tested

- A builder other than the owner, and a second kit.
- Updates over the LAN listener.
- More than one gadget downloading at once on a real relay (unit-tested only).
- Commands during a download on the kit (host-tested only).
- Anti-rollback, secure boot and flash encryption (documented only, ADR 012 §8).
